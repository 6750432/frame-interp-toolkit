DSH Pet 素材定制插帧工具 · 「打不开」急救单
Windows / Linux / macOS 都看这一份

这份文件只讲一件事：双击了，但窗口没出来 / 黑框一闪就没了。
真正干活时出的错（找不到 ffmpeg / rife 之类），看同目录
「说明书-保姆级教程.txt」里的【出问题了？先照这张表对号入座】。


────────────────────────────────────────────────────────────
【第 0 步 · 先确认两件跟系统无关的事】
────────────────────────────────────────────────────────────

  ■ 一、包下对了吗

      Windows        → 开箱即用版（80 多 MB，什么都内置）
                       或 精简版-Windows（自己已经装好 ffmpeg/rife 的用）
      Linux          → 精简版-Linux
      macOS          → 精简版-macOS

      从 v0.8 起**一个包只管一个系统**：Windows 包里只有 .bat、
      Linux 包里只有 .sh、macOS 包里只有 .command。
      所以你要是看到 .exe/.bat，那说明下成 Windows 包了 ——
      不是坏了，是下错包了。

  ■ 二、解压了吗

      几个包都要求：**先解压，再运行**。
      在压缩包窗口里直接双击里面的脚本，十次有九次跑不起来。
      解压出来是一个文件夹，脚本在文件夹里。

      而且每个包顶部都放了一张「0-先读这个（第一次用）.txt」，
      只讲你这个系统该点哪个 —— 拿不准就先看它。

  另外：**每个包里都有一个「自检」文件夹** ——
  先双击里面的「一键自检」，它会拿自带的素材真跑一遍，
  生成一份「自检报告.txt」，缺什么、错在哪一眼就看得出来。
  （自检本身也需要 Python，见下面 Windows 第 2 条。）


────────────────────────────────────────────────────────────
【Windows 用户看这里】
────────────────────────────────────────────────────────────

  ■ 双击了，黑框一闪就没了，什么都没看清

      这说明脚本真的跑起来了，只是报错一闪而过。让它停住：

        1. 按 Win + R，输入 cmd，回车
        2. 在黑框里输入 cd /d "解压出来那个文件夹的路径"
           （偷懒办法：把文件夹从资源管理器直接拖进黑框，路径自动填好）
        3. 输入 启动界面.bat  回车

      这回报错就留在屏幕上了，截图发群里就行。

  ■ 提示「python 不是内部或外部命令」/ 装了 Python 还是这么提示

      装 Python 时没勾「Add Python to PATH」。两个办法：

        ① 重装一遍 Python —— 安装第一屏底下那个勾一定要打上，
           不勾后面全废；
        ② 不想重装：去「设置 → 应用 → 高级应用设置 → 应用执行别名」，
           把 python / python3 相关的几个别名关掉再试。

      下载地址（挑 3.10 以上的稳定版）：
          https://www.python.org/downloads/

  ■ 弹出「Windows 已保护你的电脑」/ 杀毒软件报毒

      .bat 就是个纯文本批处理，报毒基本都是误报
      （因为它会去调用 ffmpeg 和 rife，行为特征像）。
      点「更多信息」→「仍要运行」；被杀软拦了就加个信任。

      实在不放心：右键 .bat →「编辑」，自己看里面写了什么 ——
      一共就几行，看得懂的。

  ■ 解压出来的路径又长又全是中文，或者放得很深

      换个短路径再试，比如 C:\插帧工具。
      本工具自己做了中文路径的处理，但换成短路径能排掉一大类玄学问题。

  ■ 双击「启动界面.bat」没反应，但双击「一键插帧.bat」能跑

      说明是图形界面那边的问题。先用命令行版把活干了（功能一模一样），
      然后把「自检报告.txt」发出来就行。


────────────────────────────────────────────────────────────
【Linux 用户看这里】
────────────────────────────────────────────────────────────

  ■ ① 窗口其实开了，只是躲在别的窗口后面

      症状：双击之后"什么都没发生"，但任务栏上多了一个图标。
      办法：Alt + Tab 切一圈，或者直接点任务栏上那个图标。

      为什么：脚本手动启动时不一定抢得到前台焦点，
      如果前台正好是全屏游戏、ToDesk 之类置顶窗口，它就被压住了。
      （v0.8 已经加了"启动后自动往前顶 0.7 秒"，
        大多数情况下不必再手动找它。）

  ■ ② 双击之后没执行，反而把脚本当文本打开了（满屏代码）

      症状：双击「启动界面.sh」，出来的是一屏代码，程序一点动静都没有。
      原因：Linux 的文件管理器默认不执行脚本；而 Thunar（Mint 自带）
      的默认动作是「用文本编辑器打开」—— 连问都不问一句。

      最省事的办法（不用改任何设置）：
        在工具包文件夹里，空白处右键 →「在这里打开终端」，然后跑
            bash 启动界面.sh
        或者直接开个终端，把下面这行整个粘进去回车：
            bash ~/下载/DSH-Pet-插帧工具包-Linux/启动界面.sh
        （路径按你实际解压的位置改）

      ★ 想以后能双击（推荐）：
            bash 装个桌面图标.sh
        跑一次，它会在你桌面放一个图标（应用菜单里也有一份），
        以后双击那个就行 —— 不受这条策略影响，也不用改任何系统设置。
        工具包挪了地方的话，重新跑一次这个脚本即可。

      想把这个默认动作改掉（不推荐，不如上面那条省事）：
        Thunar → 编辑 → 首选项 → 高级 → 安全性 → 勾上「执行 Shell 脚本」
        ⚠️ 勾完不一定立刻生效，重启一次文件管理器（或注销重进）最保险。
           而且勾上之后，**任何**可执行文本文件双击都会直接运行 ——
           从网上下载来的 .sh 记得先看清楚再双击。

      还有一种情况：有些文件管理器会弹个「执行 / 打开 / 取消」的小窗，
        那就选「执行」—— **别选「打开」**，选「打开」出来的就是代码。

  ■ ③ 脚本丢了「可执行」权限

      症状：双击完全没反应，或者提示「权限不够 / Permission denied」。
      原因：从压缩包解出来、或用 U 盘 / 网盘中转时，
      可执行位常常会掉，这是 zip 和网盘的通病，不是谁打包打坏了。

      办法 A（最省事，不需要任何权限）——
      打开终端，进到工具包文件夹，把下面这行复制进去回车：

          bash 启动界面.sh

      不知道怎么写路径？在文件管理器里进到那个文件夹，
      空白处右键 →「在这里打开终端」，然后跑上面那行就行。

      办法 B（想彻底修好）—— 在那个文件夹里跑：

          chmod +x 启动界面.sh 一键插帧.sh
          chmod +x 自检/一键自检.sh

  ★ 三种都试完还是没动静，说明是真的报错了，去看【让终端把错误说出来】。


────────────────────────────────────────────────────────────
【macOS 用户看这里】
────────────────────────────────────────────────────────────

  ■ 双击提示「无法打开，因为它来自身份不明的开发者」
      右键（或 Control + 单击）→「打开」→ 再点一次「打开」，可以绕过一次。
      或者去「系统设置 → 隐私与安全性」里点「仍要打开」。

  ■ 双击完全没反应
      多半也是丢了可执行位：
          chmod +x 启动界面.command 一键插帧.command
          chmod +x 自检/一键自检.command

  ⚠️ macOS 上这个工具**没有在真机上验证过**（手里没有 Mac）。
      遇到问题请把终端输出发群里，别自己硬扛。


────────────────────────────────────────────────────────────
【让终端把错误说出来（三系统通用）】
────────────────────────────────────────────────────────────

  GUI 版双击看不到报错，是因为那个窗口一闪就关了。
  在终端 / 命令行里跑一次，报错就会留在屏幕上：

      bash 启动界面.sh          （Windows：启动界面.bat）
      bash 启动界面.command     （macOS）

  把屏幕上那段字截图发群里就行，不用自己看懂。
  下面几条是最常见的，能自己修：

  ■ ModuleNotFoundError: No module named 'tkinter'
      你的 Python 没带图形界面库（Linux 上它常常是单独一个包）。
        Ubuntu / Debian / Mint ： sudo apt install python3-tk
        Fedora                 ： sudo dnf install python3-tkinter
        Arch                   ： sudo pacman -S tk
        macOS（Homebrew）      ： brew install python-tk

      不想装也没关系 —— 命令行版不需要它，一样能用：
        bash 一键插帧.sh

  ■ No such file or directory / 系统找不到指定的路径
      你不在工具包文件夹里。先 cd 进去，或者写完整路径。

  ■ $'\r': command not found ／ 满屏幕的 ^M
      脚本的行尾被 Windows 编辑器改成 CRLF 了。
      在终端里跑一次：

          python3 插帧.py          （Windows：python 插帧.py）

      它会自动把同目录所有脚本的行尾修回 LF，并告诉你改了哪几个。
      （.bat 是 Windows 文件，故意保留 CRLF，不在修复范围。）

  ■ python3: command not found / 没找到 Python
        Ubuntu / Debian / Mint ： sudo apt install python3
        macOS                  ： brew install python
        Windows                ： 见上面「Windows 用户看这里」第 2 条

  ■ 没检测到图形环境（DISPLAY 是空的）
      你是在 SSH 里跑的，那边没有画面可显示。
      换成命令行版：bash 一键插帧.sh
      或者用 ssh -X 连过来。

  ■ 窗口一个都不弹，命令直接结束、退出码不是 0
      把终端里那段输出发群里，这种多半是系统库版本对不上。

  ■ 第一次启动卡了十几秒才出窗口
      正常。第一次要 import 一堆东西，之后会快很多。


────────────────────────────────────────────────────────────
【万一 GUI 就是打不开，活照样能干】
────────────────────────────────────────────────────────────

  这个工具本来就有命令行版，功能一模一样，只是没有界面：

      bash 一键插帧.sh                   把 input/ 里的素材全跑一遍
      bash 一键插帧.sh 素材.webm      只跑指定的一个文件
      python3 插帧.py --检查             看看 ffmpeg / rife 认到没有

      （Windows 把 bash 换成双击、或者用 python 插帧.py）

  命令行版没有任何图形依赖：tkinter 缺失、没有 DISPLAY、
  远程 SSH 里，都能跑。GUI 只是给参数套了个可视化外壳。

  **所以「界面打不开」不等于「工具不能用」。** 先用命令行版把活干了。
