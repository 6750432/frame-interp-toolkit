DSH Pet 素材定制插帧工具 · 保姆级说明书

────────────────────────────────────────────────────────────
【零】这工具是干嘛的
────────────────────────────────────────────────────────────
把 webm 视频补帧：24fps 插成 48 / 72 / 90 / 120fps，
保留透明通道，输出还是能直接用的 webm。只做插帧，不做超分。

名字里虽然有「DSH Pet」，但任何 webm 都能用，不是只给桌宠素材的。
实测跑通过的素材类型：

  · VP9 + 透明通道（桌宠素材、动态壁纸）  → 透明通道原样保留
  · 不透明 VP9（普通视频、录屏）          → 输出也不会多塞没用的 alpha
  · VP8（老编码的 webm）                  → 自动识别，输出转成 VP9
  · 各种分辨率（320×240 / 360×200 / 640×360 / 1280×720）
                                          → 尺寸不用凑整
  · 带音轨的 webm                         → 音轨原样搬过去，不重新编码

说人话：带透明的它不会给你弄丢，带声音的它不会给你弄没。
市面上一堆插帧工具是出 mp4 的，而 mp4 的 H.264 根本没有透明通道，
素材一过就平了 —— 这个工具只出 webm，就是为了保住透明。

还有一句得说在前面：这是个可选的周边工具，不是官方补丁，
也不会去改主仓库。用不上完全不用理。


────────────────────────────────────────────────────────────
【先认清自己在哪一页：界面上一共三种模式】
────────────────────────────────────────────────────────────
打开界面，左上角有三个选项，点一下就切：

  插帧   最常用：只给视频补帧。这份说明书从【第一步】到【第六步】
         讲的都是这一页。第一次用就打这个。
  音频   只修声音，完全不碰画面 —— 后面有一整章【音频快修】讲它。
         纯音频文件（mp3 / wav / flac 之类）也能直接拖进来。
  视音   一次干两件事：画面插帧 + 声音修复，最后把修好的声音
         封回视频一起给你（视频流不重编码）。

三个模式的设置各存各的，互不干扰：在「音频」页改了强度，
不会影响「插帧」页的帧率。

左下角那块**黑色的「运行日志」三种模式共用一块**，切模式不会把它藏起来 ——
音频那边每一行实测数据（源、修复前、EQ 后实测、增益策略、频段自检、
修复后、剪掉多少静音）都会打进这里，不用开终端也能看全过程。
窗口会自己按你的屏幕算大小和位置，保证最下面这块日志不会被屏幕边缘切掉。


────────────────────────────────────────────────────────────
【支持哪些格式（全自动，你什么都不用管）】
────────────────────────────────────────────────────────────
输入：不用挑，脚本自己认。认得这些后缀 ——

    .webm .mkv .mp4 .mov .m4v .avi .wmv .flv .ts .m2ts
    .mpg .mpeg .ogv .3gp .webp .gif .apng

    编码也是自动认的：VP9 / VP8 / AV1 / H.264 / MPEG-4 …… 都行。

输出：**永远是 .webm**。

    为什么这么死板：带透明通道的视频，实际能用的容器只有 webm。
    而且 ffmpeg 是按"后缀"选封装格式的，不写死的话，mp4 喂进去会
    原样吐一个 mp4 出来（里面塞着 VP9、透明还丢了），等于废文件。

音轨：自动处理。

    opus / vorbis（webm 原生的）  →  原样复制，零损失
    aac / mp3 / ac3 …（装不下的）  →  自动转成 opus
    ——不转的话 ffmpeg 会直接拒绝写文件、整个失败。

    ⚠️ 有一堵墙是修不动的：**mp4 / mov 容器装不下透明通道**。
       带 alpha 的素材一 remux 进 mp4，透明就没了（yuva420p → yuv420p）。
       这是格式的限制，不是工具的毛病 —— 工具能做的最多是
       "把 mp4 里的画面读出来、插完帧再装回 webm"，
       但素材在 mp4 里的时候就已经没有透明了，变不回来。


────────────────────────────────────────────────────────────
【第一步】装 Python
────────────────────────────────────────────────────────────
需要 Python 3.8 或更高（实测 3.10 / 3.12 都通过）。
去 python.org 下载安装。

  ⚠️ Windows 用户注意：安装时务必勾上「Add Python to PATH」。
     不勾的话后面双击脚本会找不到 python，全废。

这个工具「不需要 pip install 任何东西」，一个第三方库都不用装。
（故意的 —— 依赖越少，越不容易在别人机器上装不上。）


────────────────────────────────────────────────────────────
【第二步】放 ffmpeg
────────────────────────────────────────────────────────────
ffmpeg 负责拆帧、合帧、编码。

  Windows：去 https://www.gyan.dev/ffmpeg/builds/
           下 ffmpeg-release-essentials.zip
           解压后，把 bin 文件夹里的 ffmpeg.exe 和 ffprobe.exe
           两个文件，直接复制到本工具包目录下（和 插帧.py 放一起）

  macOS：  brew install ffmpeg

  Linux：  sudo apt install ffmpeg      （Debian / Ubuntu / Mint）
           sudo dnf install ffmpeg      （Fedora）


────────────────────────────────────────────────────────────
【第三步】放 rife-ncnn-vulkan
────────────────────────────────────────────────────────────
这是插帧本体，真正干活的那个（它跑显卡）。

  下载页：https://github.com/nihui/rife-ncnn-vulkan/releases
  国内直连 GitHub 经常打不开，加个中转前缀就行：
          https://gh-proxy.com/https://github.com/nihui/rife-ncnn-vulkan/releases

  选自己系统的那个包，下载解压，把「整个文件夹」放到本工具包目录下。
  （也可以放别处，然后在 config.json 里把「rife可执行文件路径」
    填成绝对路径 —— 但大多数人不用这么麻烦。）

  🍎 macOS 用户注意：macOS 的发布包是个 rife-ncnn-vulkan.app 包。
     整个 .app 丢进工具包目录就行，「不用进去翻可执行文件」 ——
     脚本会自己穿进 .app 里找，也会自动去 Contents/Resources/ 找模型。
     另外 macOS 会给下载来的程序打「隔离标记」，脚本已经自动帮你放行了。


────────────────────────────────────────────────────────────
【第四步】先验证环境（强烈建议，能省掉九成的"跑不起来"）
────────────────────────────────────────────────────────────

  ── 方式 A：一键自检（最省事，双击就行）──

  工具包里有个「自检」文件夹，双击里面的：

      Windows          自检/一键自检.bat
      Linux            自检/一键自检.sh
      macOS            自检/一键自检.command

  它会拿自带的两个测试片段**真跑一遍完整流程**（插到 48fps），
  再生成一份「自检报告.txt」，里面记着：系统与 Python 版本、
  各种编码（查中文乱码全靠这几行）、ffmpeg / rife 找到没有、在哪、
  转换跑通没有、输出规格对不对。

  报告结尾说「🎉 全流程通了」，你就可以放心进【第五步】。
  说缺东西，它也会告诉你缺哪个、去哪下 —— 不会报错崩掉。

  它跟正式工具**共用同一套查找规则**：config.json 里填过路径就优先
  用你填的，没填就跟正式工具一样去 PATH 和目录里找。所以两边结论
  要是不一致，那就是 bug，把两份输出一起发出来就行。

  （跑完会多出一个「自检输出/」文件夹，是测试产物，随手删掉不影响。）

  ── 方式 B：命令行检查（想看得更细的时候用）──

  打开终端 / 命令行，切到工具包目录，跑：

    python 插帧.py --检查

（macOS / Linux 上可能是 python3）

正常的话你会看到三段东西：

  1. 找到的 ffmpeg 和 rife 路径
  2. 可用显示设备列表 —— 长这样：

       可用显示设备（rife 自己报的，不是你猜的）
例：
          [0] NVIDIA GeForce RTX 2060  〔独显〕  ← 用这块
          [1] Intel(R) HD Graphics 530 (SKL GT2)  〔核显〕
          [2] llvmpipe (LLVM 20.1.2, 256 bits)  〔软件渲染·极慢〕
       已自动绑到 [0] NVIDIA GeForce RTX 2060 上（独显）。

  3. 最后一句「环境没问题，把素材丢进 input/ 就能开跑了」

这一段「显示设备列表」值得多看一眼：
它让 rife 自己报出机器上所有能算的图形设备，然后脚本自动挑一块独显绑上。
如果里面只出现 llvmpipe（或者一个都没有），说明你的显卡驱动没装好，
现在跑的是 CPU 软件渲染，会慢几十倍 —— 这种情况脚本会明确警告你。


────────────────────────────────────────────────────────────
【第五步】放素材、开跑
────────────────────────────────────────────────────────────
两种用法，挑一种：

  ── 方式 A：图形界面（推荐，鼠标点两下）──
  双击「启动界面」（Windows .bat / Linux .sh / macOS .command），然后：

     ① 点「选择…」挑源素材文件夹（默认就是本目录下的 input/）
     ② 点「选择…」挑输出文件夹（默认 output/，选新源目录时会自动跟着变）
     ③ 在「目标帧率」里填个数字，或者点左边那几个快捷键
     ④ 点「▶ 开始插帧」，等日志框把进度刷完

  ── 关于那五个快捷键（v0.8 新加的）──
      [省电] [均衡] [丝滑] [高帧高画质] [全都拉满]

      点一下只是**帮你往输入框里填个数字**，填完照样能手改，
      输入框不会锁死。倍数是按你素材的真实帧率算的：源 24fps 时
      省电=48 / 均衡=72 / 丝滑=120 / 高帧高画质=144 / 全都拉满=192。

      「全都拉满」会弹确认框，里面有个「先试一个文件」——
      选它这一趟只跑 1 个素材，而且**只在内存里生效，不会改你的配置**。

      如果检测到你在用软件渲染（没有显卡驱动），几个高帧快捷键会自动变灰。

  ── 右边那块是干嘛的 ──
      点「开始插帧」之后，右边会做一次体检并显示三块东西：

        · 显示设备 —— 哪块显卡在干活、是独显还是核显
        · 素材规格 —— 你素材的尺寸、帧率、帧数、有没有透明、有没有音轨
        · 预估表   —— 固定 9 档帧率的预估耗时和体积

      这些**只是给你看的**，不会改任何流程。表底那句「基于本机实测外推，
      不包含桌宠渲染负载」是实话：预估不是承诺。

  ── 卡住了怎么办 ──
      点界面右上角的 [?]。里面有三步上手、要准备什么、文件怎么摆的
      目录树、下载链接（都走国内中转，旁边有「复制」按钮），
      还有常见问题。**第一次启动会自己冒一张小卡片，那也是个路标。**

  跑的时候界面不会卡死（插帧跑在后台进程里），可以放着不管它。

  ── 方式 B：命令行（极客用）──
     第 1 步  把要插帧的 webm 素材丢进 input/ 文件夹
     第 2 步  双击「一键插帧」（Windows .bat / Linux .sh / macOS .command）
     第 3 步  去 output/ 里拿结果

  命令行版支持更多参数，跑 python 插帧.py --help 看全部。

  💡 第一次跑建议先只放 1 个文件试水。命令行版可以把 config.json 里的
     「只处理前N个文件」设成 1。

  ── 素材放哪、结果去哪（路径规则）──
  放哪都行，不用非得用工具包里的 input/。规则是这样：

     图形界面：源选在 D:\素材，输出框没动
              → 输出自动跟着变成 D:\素材_插帧输出
     图形界面：你自己改过输出框
              → 尊重你选的，不再自动跟随
     命令行：  python 插帧.py D:\素材
              → D:\素材_插帧输出
     命令行：  python 插帧.py D:\素材 --输出 E:\结果
              → E:\结果
     什么都不给（默认）
              → 工具包自带的 output/

  两个细节：
  · 输出目录「刻意不放进源目录里面」 —— 因为输出也是 .webm，
    放进源目录的话，下次再跑会把上一轮的产物当素材又插一遍，越滚越大。
  · 输出目录带源目录的名字，这样处理好几套素材时不会互相覆盖同名文件。


────────────────────────────────────────────────────────────
【第六步】拿结果
────────────────────────────────────────────────────────────
输出在 output/（或者上面说的「源目录名_插帧输出」）里，
文件名和源素材一样，可以直接塞回桌宠的素材目录。

  ⚠️ Windows 自带的「电影和电视」播放器「不支持 VP9 + 透明」，
     打不开或者看不见画面是正常的，别以为文件坏了。
     要看效果用 PotPlayer / VLC，或者直接丢回桌宠里看。

  支持「续跑」：跑到一半断了、或者中途加了新素材，
  再跑一次就行 —— 已经生成好的会自动跳过。


────────────────────────────────────────────────────────────
【音频快修（可选功能：只修声音，不碰画面）】
────────────────────────────────────────────────────────────
左上角切到「音频」模式，看到的那块面板就是它。

  ■ 它能治什么
    · 听着发闷、糊成一团（能量全堆在 80~300Hz，高频没东西）
    · 忽大忽小：安静的段落听不见、响的地方又顶到头
    · 录得太小声，想拉到平台标准响度（默认 -16 LUFS）
    · 前头/后头一大段纯静音，白占体积

  ■ 它治不了什么（先说清楚，省得白忙）
    · 底噪、电流声、风声这类持续噪声 → DSP 只能压一点点
    · 隔壁说话、键盘声这类突发杂音 → 治不了
    · 音质本身已经烂了（低码率、削顶失真）→ 修不回来
    这几样得靠外挂 AI 模型，见下面「想上 AI 模型」。

  ■ 怎么用（三步）
    第 1 步   左上角切到「音频」
    第 2 步   点「选文件…」挑一个，或者「选文件夹…」整批跑
              （mp3 / wav / flac / m4a / opus / ogg / aac 都行；
                视频文件也能丢进来 —— 只抽它的声音修）
    第 3 步   点「▶ 开始音频修复」，跑完点「📂 打开输出文件夹」

    默认配置就是按「手机录的语音 / 环境音」调的，一般直接跑就行。

  ■ 面板上那几个旋钮是干嘛的
    强度        轻 / 标准 / 重。管「去闷」和「提清晰度」的力度。默认「标准」。
    精修/超精修 要不要叫外挂 AI 模型（默认关，只用自带的粗修）。
    EQ 风格     语音 / 环境音。**这是最容易白跑一趟的一个**：
                  · 语音   低频用搁架衰减，治人声发闷
                  · 环境音 低频峰值切除打在 220Hz，治音乐 / 环境音
                           把能量全堆在 80~300Hz 那种闷
                实测同一条素材：语音风格只动了 0.1 dB（≈没动），
                环境音风格能压 4~8 dB。拿不准就两个都跑，听哪个顺耳。
    响度 LUFS   默认 -16（主流平台标准）。想更响填 -14，想留动态填 -18。
    削峰策略    保真 / 保响度，这条影响很大，值得看一眼：
                · 保真（默认）源峰值本来就顶到 0 时，宁可整体小声也不削峰。
                  实测：源 +0.63 dBTP 的助眠素材，EQ 又把峰值顶高 3.2 dB，
                  保真只敢加 -5.86 dB，**最后比目标小声 6.5 dB**。
                  日志和记录里会直接写「比目标低 x.x dB」，不用你自己猜。
                · 保响度   按目标响度来，超出的峰交给限幅器。同一条素材
                  实测落到 -16.04 LUFS（目标 -16），代价是动态 4.3 → 3.5 LU。
                选哪个：要"不能有一点压限痕迹"就用保真；
                要"音量必须到位"就用保响度。拿不准就各跑一遍对着听。
    输出格式    opus（体积最小）/ mp3（兼容最好）/ flac（无损）/ wav（最大）。
    输出方式    音频 = 只出音频文件；
                视频 = 把修好的音轨**封回原视频**（视频流原样复制、不重编码）。
                选「视频」时会自动关掉「裁静音」—— 视频长度由画面定，
                把音频剪短了尾巴会没声音。
    去齿音      关（默认）/ 轻 / 标准 / 强。专门治「人声发尖、齿音刺耳、有细碎的
                咔哒声」这类**瞬时尖刺**。做法是：把信号分成两路，一路不动，
                另一路只留 5~10kHz 当"探头"，**只有尖刺冒出来那一瞬间才压一下**，
                平时完全不动 —— 所以它不会像"把高频整体削下去"那样让人声发暗。
                实测同一条素材：轻 / 标准 / 强 分别把 5~10kHz 的尖刺压低
                3.0 / 5.7 / 7.3 dB，而整体响度仍然打在目标上（偏差 ≤0.23 dB）。
                ⚠️ 它治的是"一阵阵刺"，不是"一直很亮"：如果你的素材高频
                   从头到尾都亮，它帮不上忙 —— 那种情况调「EQ 风格 / 强度」。
    压底噪      关（默认）/ 极轻 / 轻 / 标准 / 强。**噪声门**，治的是
                「安静段落里那层嘶声」。主要配 AI 模型用 —— 神经声码器
                （VoiceFixer 那类）会把整段重新合成一遍，**顺带带进一层本底噪声**：
                实测一条素材尾部本来是 -240 dB 的真·数字静音，
                过完模型就变成 -64 dB 的嘶声，音量一开大就听见。
                「轻」档（实测选定）能压到 -98.7 dB，而内容中位数、响度、动态
                三项完全没动；可用音量阈值能从 65% 提到 70%。
                ⚠️ 不要贪「标准 / 强」：底噪是更低（-107 dB），
                   但门动作更明显，听感反而差一点。**底噪听不出来就够了。**
    裁掉静音    超过 0.5 秒的纯静音自动剪掉（中间的、尾巴的都剪）。默认开。
    降级提醒    外挂 AI 出问题时要不要在日志里打一行 ⚠️。默认开。

  ■ 怎么知道它到底起没起作用（很重要）
    这不是「感觉好像好一点」型工具，跑完会给证据：
    · 界面上直接显示修完的响度、峰值、剪掉了多少秒静音
    · 输出目录里有一份《音频修复记录》：每个文件走了哪条链路、
      用了什么参数、有没有降级，都写着
    · 左下角「运行日志」里能看全过程：每个阶段的小标题（【源】/修复前/
      EQ 后实测/增益策略/频段自检/修复后/剪掉静音）都会打出来，
      和终端里跑命令行看到的一模一样
    · 频段自检：它会把 80~300Hz 和 1.5k~4k 这两段**实际量一遍**再对比。
      要是发现几乎没变化（比如 EQ 风格选错行了），会在记录里提醒你

    还有一句得记住：**「响度对上了」不等于「不闷了」**。
    响度是整体音量，闷不闷看的是 EQ 那两段动了多少 dB，两码事。

  ■ 想上 AI 模型（可选，默认关）
    默认只用自带的 DSP 粗修：零依赖、CPU 也很快。
    想更狠就勾「精修 / 超精修」，交给 audio_plugin/ 里的外挂模型跑。规矩：
    · 外挂不在、缺依赖、崩了、超时 → **自动降级成 DSP**，
      插帧主流程绝对不受影响，只在日志和《音频修复记录》里留一行说明
    · AI 模型通常要 Python 3.11 以上，和主工具不一定通用；
      把另一个解释器的完整路径填进 config.json 的「音频修复_Python路径」
      （留空 = 用主工具自己的 Python）
    · 实测（DPDFNet2，一条 30 秒助眠素材）：80~300Hz 只降 0.1 dB、
      1.5k~4k 降 1.2 dB、8kHz 以上降 5.9 dB，响度 -14.6 → -15.0，
      速度约 2.7 倍实时（58 分钟的素材要跑二十来分钟）。
      说人话：它主要吃高频噪声，**不负责去闷** —— 去闷还得靠上头的 EQ 风格。

  ■ 一个提醒
    音频是独立的一份输出，不会覆盖原文件，也不会动你的视频。
    只有「视音」模式才会把修好的声音封回视频。

【config.json 每个字段是啥】
────────────────────────────────────────────────────────────
用记事本打开改，改完保存再运行。路径类字段留空 = 自动在系统里找。

  目标帧率              默认 72
      想要多少帧就填多少。脚本会自己读源素材帧率、算出要插几倍。

  插帧模型              默认 rife-v4.6
      「别改」。只有 rife-v4 系列能自定义插帧倍数；
      rife-anime 只能固定 2 倍，填了别的帧率脚本会拦下来。

  使用第几块显卡        默认 auto
      auto = 自动挑一块独显绑上，一般不用动。
      懂行的想手动指定，填 0 / 1 / 2 这种数字。

  ● 一般不用动的

  性能模式              默认 auto
      自动探测电脑核数，然后自己决定用多少线程、要不要把优先级压低。
        auto = 推荐。核多就不限线程；核少就留出核给你用；
               同时把本工具的优先级压低 —— 机器闲时全速跑，
               你一用电脑它自动让路。
        全速 = 不管别人，能多快多快。
        省电 = 尽量少同时占核（活儿一样多，只是摊得更开、跑得久）。
        手动 = 线程参数完全按下面几项填的来，不动优先级。

  临时帧目录            默认空
      留空 = 自动挑。Linux/macOS 会优先用内存盘（/dev/shm）；
      Windows 会先找内存盘，没有就用系统临时目录并在日志里提醒。
      一趟插帧要拆出几百上千张小 png（几百 MB），落在机械硬盘上会把
      整台机器拖得一顿一顿的 —— 如果你系统盘是机械盘，
      把这里指到 SSD 或内存盘上能明显减少卡顿。

  使用第几块显卡        默认 auto
      auto = 自动挑一块独显绑上，一般不用动。
      懂行的想手动指定，填 0 / 1 / 2 这种数字。

  视频质量CRF           默认 32
      数字越小画质越好、文件越大。VP9 用 28~34 比较均衡。

  ● 想让它在小机器上更"温柔"再动这些

  编码速度cpu-used      默认 4
      VP9 编码器的速度旋钮，0 = 最慢最好，9 = 最快最差。
      实测：0 → 13.1 秒；4 → 7.4 秒；4 + 下面那条 → 5.4 秒。
      画质肉眼无差别，体积约 +14%。
      ⚠️ 5 / 6 反而比 4 慢（libvpx 这个参数不是单调的），4 是拐点。

  编码实时模式          默认 true
      再给编码器加一档速度（关掉前瞻）。实测还能再快 28%。
      想要极限画质可以改成 false。

  编码线程数            默认 0
      填 0 = 交给「性能模式」自动决定。
      想手动压 CPU 就填 2~3，能降一点峰值，代价是慢一点。

  rife读写线程          默认 1:2:2
      rife 自己的 读:算:写 线程数。它读写的那些 png 是 CPU 干的活，
      默认设置下 rife 会吃掉约 170% 的 CPU；改成 1:1:1 能降到 122%，
      代价是自己慢 30%。想让插帧尽量别抢 CPU 就填 1:1:1。

  ● 剩下的

  视频码率kbps          默认 0
      填 0 = 按上面的 CRF 走（推荐）。想锁死码率就填比如 800，
      此时 CRF 失效。

  保留音频              默认 true
      源素材有声音的话搬到输出里：opus / vorbis 原样复制（零损失），
      别的（比如 mp4 常见的 aac）会自动转成 opus —— 因为 webm 装不下它们。
      注意：插的是画面，声音不会被插帧。

  安全倍数上限          默认 3.0
      实测出来的安全线，见下面【安全线是怎么回事】。

  允许超过安全倍数      默认 false
      想插更高帧率就改成 true（画质风险自负）。

  只处理前N个文件       默认 0
      0 = 全部处理。想先试一两个就填 1 或 2。

  ffmpeg路径            默认空
  rife可执行文件路径    默认空
  rife模型所在目录      默认空
      留空即可，会自动找。自动找不到时再把绝对路径填进来。
      Windows 上路径里的反斜杠要写成两个，例如 D:\\tools\\ffmpeg.exe

  处理完删除临时帧      默认 true
      关掉的话拆出来的 png 会留着（很占地方，只在调试时用）。

  ■ 剩下那些「音频修复_开头」的字段

    平时不用手改 config.json。几个需要知道的：
      音频修复_处理链路        按顺序跑的链路数组，例如 ["dsp", "dpdfnet2"]
                               = 先粗修（去闷 + 剪静音），再把剩下的交给 AI 精修

    每一个字段后面都跟着一行「音频修复_xxx说明」，写的就是它的用处，
    拿不准读那一行。

【输出规格】
────────────────────────────────────────────────────────────
  容器    webm
  编码    VP9 + Alpha（yuva420p）；源素材本来没透明就输出不带 alpha
  分辨率  跟源素材一致，「不缩放」（只插帧，不做超分）
  帧率    你设定的目标帧率
  时长    与源素材一致（按「源帧数 × 目标帧率 ÷ 源帧率」算输出帧数）

  校验时注意：给 ffprobe 加 -c:v libvpx-vp9，否则它看不见 VP9 的 alpha，
  会把带透明的素材报成 yuv420p，让你以为透明丢了：

    ffprobe -v error -c:v libvpx-vp9 -select_streams v:0 \
            -show_entries stream=width,height,pix_fmt,r_frame_rate \
            -of default=nw=1 你的文件.webm


────────────────────────────────────────────────────────────
【跑得有多快、占多少硬件】
────────────────────────────────────────────────────────────
测试素材：640×360 / 241 帧 / 带透明，插到 48fps（同一台机器）。

  阶段            耗时      峰值 CPU
  拆帧            0.9 秒    ~785%（只有 1 秒的尖峰）
  RIFE 插帧       10.8 秒   ~336%
  编码            5.4 秒    ~264%
  ────────────────────────────────────
  合计            18.8 秒

四种性能模式（同一段素材实测）：

  模式     墙钟     总CPU工作量   平均占用
  旧版     27.6 秒  68.3 CPU秒    247%
  auto     19.5 秒  40.8 CPU秒    209%      ← 默认，推荐
  省电     26.8 秒  40.8 CPU秒    152%
  全速     19.9 秒  42.1 CPU秒    212%

★ 三个数字别混：
    · 总 CPU 工作量 = 真·电费。auto 比旧版少 40%。
    · 平均占用 = 你感觉得到卡不卡。省电模式把它压到 152%
      （约 1.5 个核），适合老旧笔记本。
    · 峰值 = 会不会突然卡一下。各模式差不多，因为峰值来自
      「拆帧」那 0.9 秒（8 个核全满），参数管不动 —— 但它只有 1 秒。

★ 「省电」模式其实不省电（总工作量一模一样），它是让你感觉
   得到的那部分变小：同时只占 1.5 个核，而不是 2.1 个。

内存峰值约 520 MB，显存约 460 MB（含桌面占用）。

【核显能跑吗】
能。实测同一段素材，Intel HD 530 核显比 RTX 2060 慢 3.3~3.5 倍，
时间从 18.8 秒变成约 43 秒 —— 能用，但不算快。
而且**画质一模一样**（逐像素平均差 0.0132 / 255，有些帧逐字节相同）。
注意换核显**不会增加 CPU 负担**（RIFE 是显卡干的活），只是 GPU 那步变长。


────────────────────────────────────────────────────────────
【倍数不是整数，会有问题吗】
────────────────────────────────────────────────────────────
脚本会先读源帧率，再算要输出多少帧（源帧数 × 目标帧率 ÷ 源帧率）。

  源 → 目标            倍数      齐不齐
  24fps → 72fps        3.00 倍   整数 ✔（桌宠的主场景）
  24fps → 48fps        2.00 倍   整数 ✔
  24fps → 90fps        3.75 倍   非整数
  20fps → 48fps        2.40 倍   非整数
  20fps → 60fps        3.00 倍   整数 ✔

**非整数倍也不会出错**，放心用。因为 RIFE 是「在整条序列上均匀分布」
输出帧的，出来永远是标准的固定帧率，时间轴是均匀的。
唯一的代价是内容时间轴相对于播放时间被拉伸不到 1%
（实测 20→48fps 是 0.78%）—— 肉眼看不出来。

想最干净就挑整数倍：源素材是 20fps 的话，40fps 或 60fps 最齐。

（顺带一说：这跟"降帧"不是一回事。如果某个片段的源帧率本来就不低于
 目标帧率，脚本会直接跳过它 —— 插了反而是降帧。）


────────────────────────────────────────────────────────────
【安全线是怎么回事（重要）】
────────────────────────────────────────────────────────────
默认建议：24fps 原素材插到 72fps（3 倍）就够了。

拦下来的理由「不是画质，是功耗和负载」：

  1. 144Hz 显示器 ÷ 72 = 2，整数倍不抖；
  2. CPU 代价随帧率线性涨 —— 实测 120fps 比 72fps 贵将近一倍，
     笔记本 / 小机箱容易吃不消；
  3. 画质上「没测出」 90 / 120fps 有可见鬼影（连动作最猛的片段都干净），
     但样本只有 640×360 的 Q 版片段，细线条立绘没覆盖，所以不放开。

所以脚本默认设了「安全倍数上限 = 3.0」。你填 120 而源素材是 24fps 时，
它会直接拦下来并告诉你为什么。确认要试，就把「允许超过安全倍数」
改成 true。

  如果你确实要跑 90 / 120fps，建议同时把「编码线程数」设成 2~3 ——
  实测能把 CPU 峰值压下来一大截（实测时 90fps 那批把 CPU 顶到
  75°C 触发了保护，加上线程限制之后就没再触发过）。

【出问题了？先照这张表对号入座】
────────────────────────────────────────────────────────────

  ■ 双击之后窗口没出来 / 黑框一闪就没了 / 提示权限不够
    Windows / Linux / macOS 上最常见的那些原因，单独写了一份急救单：
        同目录的「打不开看这里.txt」
    一句话版本：
      Windows → 没装 Python、没勾 Add to PATH、杀软拦截、没解压先双击
      Linux   → ① 双击没执行、反而弹出一屏代码？那是 Thunar 的默认动作，
                  在文件夹里右键 → 在这里打开终端 → bash 启动界面.sh
                ② 窗口其实开了，只是躲在别的窗口后面，Alt+Tab 一下
                ③ 丢了可执行位，同上，用终端那行命令最稳
    界面打不开也不耽误干活，命令行版永远能跑：
        bash 一键插帧.sh

  ■ 到底缺什么、错在哪，想一句话说清楚
    双击「自检/一键自检」，把生成的「自检报告.txt」发出来 ——
    系统、Python、编码、找到的程序、真跑一遍的结果，全在里面。

  ■ 跑起来报 $'\r': command not found，或者一堆奇怪的 ^M
    原因：脚本文件的行尾被 Windows 编辑器改成 CRLF 了
          （bash 只认 LF；.py / .json / .md 不受影响）。
    修法：在终端里跑一次  python 插帧.py
          它启动时会自动把同目录下 .sh / .command / .py / .json /
          .md / .txt 的 CRLF 全部修回 LF，并告诉你改了哪些文件。
          （.bat 是 Windows 原生格式，必须保留 CRLF，不在修复范围内。）
    为什么自愈放在 Python 里而不是 bash 脚本里：倒霉的 bash
    读到 CR 就已经崩了，它根本没机会自救。

  ■ 提示找不到 ffmpeg / rife-ncnn-vulkan
    跑 python 插帧.py --检查，它会告诉你缺哪个、去哪下。
    下完把文件夹放进工具包目录，或者在 config.json 里填绝对路径。

  ■ 显示设备列表里只有 llvmpipe，或者干脆一个都没有
    说明显卡驱动没装好（Vulkan 不可用），现在在用 CPU 软件渲染。
      Windows：去显卡官网装驱动，NVIDIA / AMD / Intel 的都自带 Vulkan
      Linux：  装 vulkan 驱动（mesa-vulkan-drivers 或 nvidia-driver）
    硬跑也能出结果，但一张图好几秒，十来秒的素材就是几十分钟起步。

  ■ 提示「模型 rife-anime 不支持自定义倍数」
    rife-anime 只能固定 2 倍。想用别的帧率就改回 rife-v4.6；
    如果你正好只要 48fps（2 倍），可以试试它，理论上对二次元线条更友好。

  ■ 太慢了
    插帧速度主要看显卡（核显大约比独显慢 3.5 倍，但还是能用）。
    先检查两件事：
      ① 是不是掉到软件渲染了（见上面「显示设备列表里只有 llvmpipe」那条）
      ② 「性能模式」是不是被改成「省电」了 —— 会慢 40% 左右
    另外可以按片段分批跑，脚本支持续跑 —— 已经生成好的会自动跳过。

  ■ 放了 mp4 / mkv 进去，脚本说「没有能处理的素材」
    先看它列出来的那份后缀名单。如果你那个文件的后缀不在里面，
    把它改名成对的后缀（比如 .mp4 写成 .mp4，别写成 .mp4.mp4）。
    实在不行就直接把单个文件拖进去跑：
        python 插帧.py "D:\素材\素材.mp4"
    —— 直接指定单个文件时不做后缀筛选。

  ■ 素材明明是带透明的，为什么脚本说「整段扫下来没有一处透明像素」？
    因为它真的没有。有些格式（最典型是 GIF）会声明一个透明索引，
    但从来不使用 —— 像素格式看着带 alpha，实际上每个像素都是不透明的。
    脚本会把拆出来的 alpha 帧扫一遍再决定，避免白跑一轮插帧。
    如果你确定被误判了（比如透明只出现在某一帧），
    把那个素材单独反馈给作者，会把判定改保守。

  ■ 明明放的是 mp4，为什么输出叫 .webm？
    故意的。带透明通道的视频，实际能用的容器只有 webm，
    而这个工具要保证"素材进得来、透明保住、能塞回桌宠"。
    所以输出永远统一成 .webm，不管喂进去的是什么。

  ■ mp4 素材是带透明的，插完帧透明怎么没了？
    不是工具弄丢的 —— **mp4 容器本身就装不下透明**。
    带 alpha 的素材一旦被封装进 mp4，透明通道当场就没了
    （像素格式从 yuva420p 变成 yuv420p）。这是个格式限制，
    谁来做都一样。想要透明，素材必须用 webm 或 mkv 存。

  ■ 音轨被转码了？
    对，故意的。webm 只认 opus 和 vorbis 两种音轨，你的原音轨如果是
    aac / mp3（mp4 里最常见的就是 aac），不转的话整个输出会直接失败。
    日志里会明确写「音轨是 aac，webm 装不下 → 自动转成 opus」。
    原音轨本来就是 opus / vorbis 的话，是原样复制的、零损失。

  ■ 提示「跳过：源素材已经是 xxx fps，不低于目标 xxx fps」
    说明这个片段的帧率本来就达标了，插了反而是降帧。
    脚本自动跳过它，别的文件照跑。

  ■ 嫌它占 CPU / 风扇响 / 想边插帧边用电脑
    把 config.json 的「性能模式」改成「省电」。
    实测平均占用能压到 152%（约 1.5 个核），代价是慢 40% 左右。
    默认的 auto 已经会把优先级压低 —— 你一开别的程序它就自动让路。

  ■ 解压出来文件名变成 #U4e00#U952e 这种乱码
    这是压缩包没带 UTF-8 文件名标志位导致的，跟中文名先天不合。
    本工具包是用带标志位的方式打的，正常不会出问题；
    万一还是遇到，「换 7-Zip 或 WinRAR 解压」即可，别用老命令行 unzip。
    顺带一提：桌宠发行版里那批 #Uxxxx 素材名，多半就是这个环节产生的
    —— 不是作者故意加密。

  ■ macOS 提示「来自身份不明的开发者」
    右键 → 打开 → 仍然打开。
    或者先在终端跑一次：chmod +x "启动界面.command" "一键插帧.command"

  ■ Linux 提示缺 tkinter（图形界面起不来）
    sudo apt install python3-tk        （Fedora 用 python3-tkinter）
    Linux 的 tkinter 是单独一个包，很多系统默认不带。
    不想装也没关系，命令行版完全不受影响。

  ■ 跑完发现某个片段坏了
    删掉输出目录里那一个，重新跑一次，其他的会自动跳过。

  ■ 切到「音频」模式点了开始，却什么都没发生
    先看面板上那行小字「执行顺序：…」——
    如果链路是空的，说明三个勾（粗修 / 精修 / 超精修）一个都没勾上。
    至少勾一个；勾了 AI 却没有外挂，它会自动降级成粗修跑，不会卡住。

  ■ 安静段落（尤其句子之间、结尾）能听见"嘶——"的一层底噪
    那是 AI 模型重新合成时带进来的（源素材本身可能一点底噪都没有）。
    把「压底噪」开成「轻」（先别用标准/强）。
    如果你**没用** AI 模型、只用自带 DSP，那这层底噪来自源素材本身 ——
    压底噪也能压，但压完安静段落会显得"太干净"，自己听一下取舍。

  ■ 人声发尖 / 有齿音 / 有细碎咔哒声
    先用「去齿音」，从「轻」开始试，不够再往上加。
    判断技巧：如果那些刺耳的点是**一阵阵的**，去齿音有用；
    如果是**从头到尾都亮**，那要用「EQ 风格」调（或者换「语音」风格）。

  ■ 音频修完听着跟没修一样
    九成是 EQ 风格选错了。看输出目录里的《音频修复记录》，
    里面会写 80~300Hz 实际动了多少 dB；只动了零点几 dB 就等于没动。
    把「EQ 风格」从「语音」换成「环境音」再跑一遍（或反过来）。

  ■ 音频修完变短了
    那是「裁掉静音」干的活 —— 超过 0.5 秒的纯静音被剪了。
    不想动时长就把那个勾去掉。

  ■ 音频那步报错说找不到 Python / 没有某个模块
    那是外挂 AI 模型没装好。**不影响主流程**：它会自动降级成 DSP，
    照跑不误。真要用 AI，把对的解释器路径填进「音频修复_Python路径」。
    日志里那行 ⚠️ 就是降级提示，不想看可以去掉「降级时在日志里提醒」。

  ■ 修完的音频想配回视频，但不想重新插帧
    「音频」页把「输出方式」改成「视频」，它会只换音轨、
    视频流原样复制，不重编码，很快。

【三个系统的启动方式】
────────────────────────────────────────────────────────────
  Windows   图形界面：双击 启动界面.bat（用 pythonw，不弹黑框）
            命令行：  双击 一键插帧.bat，或者 python 插帧.py
            先自检：  双击 自检\一键自检.bat

  Linux     图形界面：**开终端跑** bash 启动界面.sh
                      （Linux 上双击 .sh 会被文件管理器当文本文件打开，
                        见的是一屏代码 —— 这是它的默认策略，不是工具坏了；
                        想以后能双击就先跑一次  bash 装个桌面图标.sh ）
            命令行：  bash 一键插帧.sh
            先自检：  bash 自检/一键自检.sh

  macOS     图形界面：双击 启动界面.command
            命令行：  双击 一键插帧.command，或者 python3 插帧.py
            先自检：  双击 自检/一键自检.command

  图形界面只用 Python 自带的 tkinter，没有引入任何第三方库 ——
  不会像 PyQt 那样多出几百兆依赖，整个工具包还是几十 KB。

【还没测过的地方（自己交代清楚）】
────────────────────────────────────────────────────────────
  1. macOS 完全没在真机上跑过（手上没设备）。已经提前加固了两处最容易
     翻车的地方（.app 里找模型、Gatekeeper 隔离标记），但那都是照着
     文档写的，不是实测。
  2. AMD / Intel 显卡插帧没有在真机上验过。Vulkan 是通用的、理论上都能跑，
     自动挑卡的逻辑也覆盖了核显和 A 卡的名字特征，但没上真机。
  3. 画质只覆盖了 640×360 的 Q 版风格素材。
     细线条立绘、高速横向平移那类没有样本 —— 而 RIFE 恰恰最容易在
     那类素材上翻车。
  4. 90 / 120fps 样本偏少；8fps / 12fps 这类极低帧只测了一个片段。
  4b. 新增的那批格式（mov / avi / wmv / flv / ts / 3gp / 动图）只测了
      mkv 和 gif 两个代表，别的是照着同一套逻辑放开的，没有逐个实跑。
      webp / apng 动图没找到能生成带透明样本的工具，一次都没跑通过。
  5. ★ 工具里没有任何「重影修复」后处理。RIFE 出什么就是什么，
     脚本只是 拆帧 → 插帧 → 合帧 → 编码。
     上面所有"没看出鬼影"的说法，只代表在这批素材上没看出问题，
     不代表它在任何素材上都不会出鬼影。

  6. 音频快修这一整套**只在 Linux 上实跑过**，Windows / macOS 一次没跑。
      AI 外挂也只真跑过一个模型（DPDFNet2，权重不在工具包里、
      得自己下）；另外两个槽位（gtcrn / frcrn）目前是空壳 ——
      选了不会崩，会走「降级成 DSP」那条路，但也不会真的跑模型。
      DSP 那套的参数是按几条实测素材定下来的，换成别的素材
      （纯音乐、乐器、多人说话）不一定一样好用。所以每次跑完都会留一份
      《音频修复记录》，请以那份实测数字为准，别信"感觉好一点"。
