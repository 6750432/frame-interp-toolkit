────────────────────────────────────────────────────────────
v0.7   性能大改 + 调度自适应 + 全格式自动识别
────────────────────────────────────────────────────────────

这一版的主线是一句话：**别再让用户配参数了。**

【一、编码提速：一行参数换来一半时间】

把整条流水线逐段计时之后发现了一件反直觉的事 —— 最贵的不是插帧，
是编码：占了总耗时的 52%。而 VP9 的编码速度旋钮本工具一个都没设，
ffmpeg 的默认值是「最慢最好」。

实测（241 帧素材、640×360、带透明）：

    设置                        耗时      峰值CPU    体积
    cpu-used=0（原来的默认）    13.09 秒   364%      1257 KB
    cpu-used=4                   7.40 秒
    cpu-used=4 + realtime        5.35 秒   264%      1435 KB

时间砍 59%、峰值 CPU 从 364% 降到 264%、画质 SSIM 0.9964（肉眼无差别），
代价只是文件大 14%。

    ⚠️ 顺便挖出一个反直觉的坑：cpu-used=5 / 6 反而比 4 慢 ——
       libvpx 配合 -row-mt 时这个参数不是单调的，4 才是拐点。

另外把「拆帧」从调用两次 ffmpeg 改成一次（用 split 滤镜同时出彩色和
透明两组），省掉一遍源视频解码；「源素材被 ffprobe 重复探了 4~6 次」
也顺手修了（批量跑时是分钟级的浪费）。

**整条流水线：25.1 秒 → 18.8 秒。**

【二、调度自适应：机器闲时全速，你一用电脑它就让路】

新增一个「性能模式」配置，默认 auto。它会：

    · 探核 —— 用 sched_getaffinity 而不是 os.cpu_count()，
      被 taskset / cgroup 限制过也能算对
    · 按核数分配 —— 实测本工具的编码只吃约 2.2 个核，所以核多的
      机器根本不限线程（限了只是白白变慢）；只有 4 核及以下才限制
    · 压低优先级 —— Linux/macOS 用 nice -n 10 + ionice -c 3（IO 降到
      空闲级）；Windows 用 BELOW_NORMAL_PRIORITY_CLASS
    · 把决定过程打进日志，不玩黑箱

为什么用 nice 而不是"少开线程"：
    · 机器闲着的时候，nice 0 和 nice 19 都是 5.9 / 6.2 秒 —— 零成本
    · 机器被压满的时候，nice 19 把对用户的干扰从 +11.5% 降到 +5.2%
    · 也就是说：**闲时全速抢，忙时自动让路**，内核免费帮你仲裁

实测四种模式（同一段素材）：

    模式     墙钟     总CPU工作量   平均占用   说明
    旧版     27.6 秒  68.3 CPU秒    247%      ——
    auto     19.5 秒  40.8 CPU秒    209%      推荐
    省电     26.8 秒  40.8 CPU秒    152%      活儿一样多，但摊薄了
    全速     19.9 秒  42.1 CPU秒    212%      不管别人

    ★ 注意「省电」的真实作用：它**不省电**（总工作量一模一样），
      它是让你感觉得到的那部分变小 —— 同时只占 1.5 个核而不是 2.1 个。

【三、中间帧自动挑盘】

一趟插帧要拆出几百上千张小 png（几百 MB）。这些文件落在机械硬盘上，
会把整台机器拖得一顿一顿的 —— 这比吃 CPU 更容易让人骂人。

    Linux/macOS：优先 /dev/shm 或 /tmp（只要确认是内存盘）
    Windows     ：优先找虚拟内存盘（GetDriveTypeW 能认出来），
                  没有就用 %TEMP% 并在日志里提醒
    也可以自己指定「临时帧目录」

【四、全格式自动识别（这条是为了防"作者以后换码"）】

起因是有人问：作者说以后可能要换素材格式，换 MP4 行不行？

一测发现三个真 bug：
    · 目录模式只认 .webm 后缀 —— **.mkv 被冤枉了**
      （它和 webm 同属 Matroska 家族，透明明明保得住，却被跳过）
    · 输出后缀跟着输入走 —— mp4 喂进去会原样吐一个 mp4，
      里面塞着 VP9、透明还丢了，等于废文件
    · 音轨无脑原样搬 —— 遇到 mp4 常见的 AAC，webm 装不下，
      ffmpeg 直接 "Could not write header" 整个失败

改完之后：
    · 输入认 17 种后缀（webm mkv mp4 mov m4v avi wmv flv ts m2ts
      mpg mpeg ogv 3gp webp gif apng）
    · **输出永远 .webm** —— 透明只有它能装
    · 音轨自适应：opus / vorbis 原样 copy；别的一律自动转 opus
    · 解码器两段式探测：先不带解码器问一次拿编码名（快、准），
      只有 vp9 / vp8 / av1 才带显式解码器再问一次（只有这样才能
      看见 alpha）；顺带把 av1 的映射也加上了
    · 解码失败自动降级重试（万一那台 ffmpeg 没编 libdav1d）
    · 目标帧率不比源高时自动跳过（不然是"降帧"，没人想要）

实测：mkv 带透明 ✔ 透明保住｜mp4 + H.264 + AAC ✔ 自动转 opus 出 webm｜
gif 动图 ✔ 能跑｜老六种素材全回归通过。

【五、文档补了「倍数不是整数行不行」】

有人问 20fps 的素材插到 48fps（2.4 倍，不是整数）会不会出问题。
不会 —— RIFE 是在整条序列上均匀分布输出帧的，输出永远是标准固定
帧率、时间轴均匀，唯一的代价是内容时间轴被拉伸不到 1%（实测 0.78%）。
不过顺手把常见组合列了个表，想最干净就挑整数倍
（桌宠主场景 24→72 正好 3 倍，本来就是干净的）。


【六、别光听素材"声明"，得看它实际有没有透明】

拿群里抓来的一张真实 GIF 表情一试，发现它解出来的像素格式是 bgra
（= 带 alpha），可整段 100% 的像素 alpha 全是 255 —— **压根没有透明**。

而原来只认像素格式，于是：
    · 白跑一整轮 alpha 插帧（实测多花 30% 时间）
    · 输出还莫名其妙带一个全空的 yuva420p 通道

现在改成：拆完帧之后，把 alpha 那批 png 缩成 32×32 扫一遍。
只要整段没有一处透明像素，就把它当不透明处理，省掉一轮插帧。

    · 覆盖全部帧，不抽样 —— 不会漏掉"只有某几帧有透明"的情况
    · 读的是已经躺在磁盘上的 png，不用重新解码源视频，代价零点几秒
    · 拿不准一律当"有 alpha"：宁可白跑一轮，也绝不能把真的透明丢掉

实测那张 GIF：7.46 秒 → 5.51 秒（-26%），产物从 yuva420p 变成 yuv420p。
反向也验了：真带透明的 webm 和 GIF 都仍然走 alpha 全流程，没被误伤。

    ⚠️ 但有一堵墙是修不动的：**mp4 / mov 容器装不下透明通道**。
       带 alpha 的 VP9 一 remux 进 mp4，像素格式就从 yuva420p 变成
       yuv420p，透明没了。这是格式的限制，不是代码的问题 ——
       能做的至多是"把 mp4 里的画面读出来、插完帧再装回 webm"，
       但素材在 mp4 里的时候就已经没有透明了，变不回来。

v0.8   图形界面大改：左右分栏 + 环境自检 + 新手引导
────────────────────────────────────────────────────────────

这一版**底层流水线一行没动** —— 插帧/拆帧/编码还是原来那套。

【一、左右分栏】

左边（原来的那些，位置没变）：文件位置、目标帧率、日志框。
右边（新加的）：环境自检面板，三块 ——

    显示设备   哪块卡、独显还是核显、是不是掉到软件渲染了
    素材规格   第一个素材的尺寸/帧率/帧数/容器/编码/音轨/有无透明
    预估表     固定 9 档（48/60/72/90/120/144/165/180/240），
               每档给出倍数、输出帧数、预估耗时、预估体积
               绿字 = 在默认安全线内；橙字 = 超了

布局用 ttk.PanedWindow，中间的分隔条能拖。底部标注
「基于本机实测外推，不包含桌宠渲染负载」—— 预估不是承诺。

【二、五个预设按钮（只帮你填，不锁死）】

    [省电] [均衡] [丝滑] [高帧高画质] [全都拉满]

点一下只做两件事：往「目标帧率」输入框里填个数字、
在下面显示一句「源 XXfps × N = YYfps（整数倍 ✔）」。
输入框**不加锁、不禁用**，你随时能改成别的。

倍数是**按你素材的真实帧率**算的，不是写死的：源 24fps 时
省电=48 / 均衡=72 / 丝滑=120 / 高帧高画质=144 / 全都拉满=192。

「全都拉满」会弹确认框，里面有个 [先试一个文件] ——
选它本次只跑 1 个素材，**只在内存里生效，绝不写进 config.json**。

检测到软件渲染（llvmpipe）时，三个高帧预设会自动置灰。

【三、新手引导（渐进式，不打扰）】

· 首次启动冒一张**非模态**小卡片（不调 grab_set，不锁住主界面），
  可以拖到任意角落：[新手] 留着当路标 / [老手] 直接销毁并记住
· 主界面右上角常驻 [?] 按钮
· 帮助面板底部有 [ ] 以后启动就自动打开这份帮助（写进 config）
· 帮助面板内容用 pack_forget()/pack() 手写的折叠区，没引任何第三方库
· 下载链接全部加了 gh-proxy 前缀，每条旁边一个「复制」按钮；
  链接本身也留在只读输入框里，能手动选中 Ctrl+C 兜底
· 写明目录树，并提醒「懒人包 / 开箱即用版」可能比最新版落后

【四、跨平台适配】

Windows（这些都是小白最容易翻车的地方）：
  · 子进程一律带 CREATE_NO_WINDOW —— 不带的话批处理时会闪几十个黑框
  · 进程优先级用 BELOW_NORMAL_PRIORITY_CLASS（Windows 版的 nice）
  · 启动时设置 DPI 感知，系统缩放 125% 时界面不会糊
  · 用 ctypes 问 Windows 要「寻道代价」属性来判断 %TEMP% 是不是机械盘
    （固态 = 0、机械 = 1；查不出来就什么都不说，绝不瞎猜）
  · 所有子进程输出强制 utf-8 + errors=replace，config 读写也带 encoding

Linux：
  · 优先级保持 nice -n 10 + ionice -c 3（IO 降到空闲级）
  · 临时目录优先内存盘（/dev/shm），没有再退到 /tmp
  · 剪贴板：X11 下 clipboard_append 之后补一次 update()，
    并且窗口不立刻销毁 —— 不然复制完内容就没了

【五、底层只加了三个「只读」的东西】

为了守「检测类 UI 只做展示，业务判断调用原有底层函数」这条红线，
底层只新增了两个只读查询入口和一行版本号，流水线一行没碰：

  · VERSION 常量 + 日志头部打印版本号
  · --列素材 <目录>   列出能处理的素材（一行 JSON）
  · --探素材 <文件>   探测规格（一行 JSON，复用底层的 probe()）

GUI 需要「有哪些素材」「第一个多宽多高」时，调的就是这两个入口 ——
不是自己再写一套 ffprobe 解析。两边共用同一份代码，永远不会各说各话。

【六、这一版没做的事（说清楚）】

  · 没做「自动降分辨率」。红线要求只做文案建议，不擅自动手。
  · 没跑满载测试。只拿一个 5 秒小样本（120 帧 → 360 帧）验证了
    GUI 不假死、日志实时刷、产物规格正确。
  · Windows 侧的新代码（黑框、DPI、机械盘检测）**没有在真机上跑过**，
    都是照着 API 文档写的，要去 Win10 上实测才算数。

【七、文档：补了一份「打不开」急救单】

v0.8 里新加了「打不开看这里.txt」。起因是有 Linux 用户反馈
双击了但窗口没出来，一查发现是三种跟工具本身无关的情况：

  ① 窗口其实开了，只是被别的窗口压在后面（不是没启动）
  ② 文件管理器弹窗问「执行 / 打开」，默认不自动执行脚本
  ③ 从压缩包 / 网盘拷过来时，脚本的「可执行位」掉了

另加顺手写进去了：tkinter 缺失怎么装、CRLF 行尾怎么自愈、
没有 DISPLAY（SSH）怎么办、macOS 的「未验证开发者」怎么绕过，
以及**命令行兜底方案** —— GUI 打不开不等于工具不能用，
`bash 一键插帧.sh` 一样干活，且完全不依赖图形库。

同时 gui.py 加了一行「启动后自动往前顶 0.7 秒」，
先解决掉最常见的那一种（窗口躲在后面）。

后来发现这份东西只覆盖 Linux / macOS 太亏了 —— 群里大部分是 Windows
用户。所以又补了一整节 Windows 的：黑框一闪看不见报错怎么让它停住、
Python 装了还是提示找不到（Add to PATH）、SmartScreen 和杀软的误报
怎么绕过、中文长路径的玄学问题。文件也顺势改名成「打不开看这里.txt」，
三个系统共用一份。


【八、自检并进工具包了（少下一个包）】

以前自检和工具包是**两个 zip**：先下「快速自检包」跑一遍，再下工具包
干活。现在合成一个了 —— 「自检」是工具包里的一个子目录，解压一个包，
先进「自检」双击一遍，再干活。

改动其实就三处，但都是「不做就会各说各话」的地方：

  · 自检.py 的查找根从「自己所在目录」扩成「自己所在目录 + 上一级」
    —— 因为工具包的 ffmpeg / rife 就放在上一级。上一级只在确认它真的
    是工具包目录（同级有 插帧.py）时才纳入，不然万一解压到 Downloads
    那种大目录，递归找程序能翻很久。
  · config.json 里填过路径的话，自检**优先用你填的那份** ——
    跟正式工具看同一个配置，不会出现「自检说找得到、正式工具说找不到」。
  · ffprobe 没单独找到时，顺手看一眼 ffmpeg 旁边有没有。

搜索素材的顺序也刻意定了：**自带的测试素材永远排第一**，
不去抓用户 input/ 里的真素材来跑测试 —— 那玩意儿可能几十秒长。

打包端补了一个真会出事的坑：自检报告里带着打包者本机的用户名和路径，
所以 `打包.py` 把「自检报告.txt」「自检输出/」直接列进排除名单，
绝不会打进包里发出去。


【九、修了「第一次用」小卡片飞出屏幕】

首次启动冒出来的那张指路小卡片，原来是这么摆的：

    x = 主窗口.x + 主窗口.宽 + 12

只算了「主窗口右边还剩多少」，**完全没管屏幕边界**。主窗口一宽
（1080 的窗口放在 1920 的屏幕上，右边只剩 840 像素），x 直接算到
1900 多，整张卡片飞出去，只在屏幕边上留一条，看着像坏了一样 ——
用户反馈的原话是「那个第一次用的小窗口飞到我屏幕外了」。

现在改成三级退让，保证整张卡片永远在屏幕里：

    ① 主窗口右边放得下   → 摆右边（原来的行为，不挡主界面）
    ② 右边放不下         → 摆到主窗口内部的右上角（像贴纸一样）
    ③ 主窗口快占满屏幕   → 贴着屏幕右上角放

最后再兜一次底：摆完量一遍**真实落点**，出界就硬拉回来 ——
防的是缩放、多屏这些算不准的情况。实测（1920×1080、主窗口
1080 宽）：卡片从 x=1888 挪到 x=1490，右边缘 1900，整张都在屏内。


【十、按系统分包：一个 zip 只管一个系统】

以前的精简版是**一个包通吃三系统**，摊开来是这样：

    启动界面.bat   启动界面.sh   启动界面.command
    一键插帧.bat   一键插帧.sh   一键插帧.command

六个长得几乎一样的文件挤在一起，用户根本不知道该点哪个 ——
点在 .bat 上没反应、点在 .sh 上弹一屏代码，还以为是工具坏了。
（真事：反馈「双击没反应，只弹出来代码」的同学就是这么撞上的。）

现在拆成三个包，每个包里**只有它自己系统的那套**：

    2-精简版-Windows-v0.8.zip    只有 .bat
    3-精简版-Linux-v0.8.zip      只有 .sh
    4-精简版-macOS-v0.8.zip      只有 .command

每个包顶部再放一张「0-先读这个（第一次用）.txt」，只讲这个系统的事。
打包脚本会自动把别的系统的启动器删掉，并在打完以后把删了哪些列出来 ——
省得哪天手滑漏裁。

【顺带解决 Linux 的「双击只弹代码」】

这件事的根子在文件管理器：Thunar（Mint 自带）双击可执行 .sh 会
**直接用文本编辑器打开，连问都不问**。这不是配置问题，去
首选项里也找不到「可执行文本文件」那个老选项了（实测过，
`misc-exec-shell-scripts` 设 0/1/2/3 全都没反应）。

所以不去跟用户的文件管理器较劲，换了条路：包里加了个

    装个桌面图标.sh

跑一次，它会在桌面上放一个 `.desktop` 图标（同时塞进应用菜单），
Exec 里写的是**这台机器上的绝对路径**（它自己 readlink 出来的）。
.desktop 不受「可执行文本文件」那条策略影响，双击一定能跑。
工具包挪位置了，重新跑一次就行。

桌面图标这条路唯一的坑：`.desktop` 里的 `%k`（自指路径）在 GIO 里
**展开成空字符串**（实测），所以没法做一个「解压到哪都能用」的
自指启动器 —— 只能靠这个脚本在本地生成绝对路径。


────────────────────────────────────────────────────────────
v0.9   音频快修：给声音也来一份「去闷 + 标准化」（当前版本）
────────────────────────────────────────────────────────────

v0.8 只管画面。这一版把声音也管起来了 —— 起因很具体：
手里有个 58 分钟的录音，前面 20 分钟是内容、后面全是一段死寂，
而且听着发闷。插帧工具本来就会读音频，顺手加一条支线，
不用再开一个软件。

仍然守两条老规矩：**主流程一行没改**、**不引入任何第三方依赖**。

【一、界面从「一个模式」变成「三个模式」】

  插帧   原来的功能，一动没动，还是默认页。
  音频   新：只修声音，不碰画面。纯音频文件也能进（mp3/wav/flac/m4a/opus…）。
  视音   新：画面插帧 + 声音修复，最后把修好的音轨**封回视频**。
         视频流原样复制、不重编码，所以只比纯插帧多花几秒。

  三个模式的设置各存各的：在「音频」页改强度不会动「插帧」页的帧率。
  音频面板是**懒加载**的 —— 不切过去就不 import，切过去失败也只少一个面板，
  不影响插帧。

【二、默认那条链路（DSP，零依赖）】

  去闷  →  响度标准化（默认 -16 LUFS）  →  剪静音（>0.5s）  →  削峰保护

  全是 ffmpeg 自带滤镜，没装任何 Python 包，CPU 也很快。

  · **EQ 风格是分开的**：语音（低频搁架衰减）/ 环境音（峰值切除打 220Hz）。
    这条是实测出来的 —— 同一条素材，语音风格只动了 0.1 dB（等于白干），
    环境音风格压了 4~8 dB。默认按素材类型给，拿不准就两个都跑。
  · **削峰策略分开**：保真（宁可整体小声也不削峰，适合助眠/音乐）/
    保响度（交给限幅器，口播用）。
    实测差异（源 -14.60 LUFS / +0.63 dBTP 的助眠素材，环境音 EQ，同一套参数）：
      保真  → 输出 -22.50 LUFS、真峰值 -1.95 dBTP、动态 4.20 LU（**比目标小 6.5 dB**）
      保响度 → 输出 -16.04 LUFS、真峰值 -0.26 dBTP、动态 3.50 LU
    也就是说：源峰值本来就顶到 0 的素材，选保真会明显变小声 ——
    这是策略本身的意思，不是 bug。所以这一版在日志和《音频修复记录》里
    **直接把"比目标高/低多少 dB"写出来**，不再只给一个响度数字让人猜。
  · **剪静音会自动让路**：输出方式选「视频」时自动关掉 ——
    视频长度由画面定，音频剪短了尾巴会没声。
  · **压底噪（噪声门）**：五档（关/极轻/轻/标准/强），专门治
    「AI 模型重新合成之后凭空多出来的那层嘶声」。
    起因很具体：一条素材尾部本来是**真·数字静音**（-240 dB，采样点全零），
    过一遍 VoiceFixer 之后变成 **-64 dB 的嘶声** —— 音量一开大就听得见。
    试过 DPDFNet2 去噪（只到 -74.6 dB）和 ffmpeg 的 afftdn 频谱降噪（-64.5 dB），
    基本没用；**只有噪声门管用**：标准档压到 -107.2 dB，
    而内容中位数、整体响度、动态范围三项一点没动。
    最后是使用者**逐条试听**选的「轻」档 —— 可用音量阈值 70%，再往上只剩失真。
    ⚠️ 这里有个反直觉的地方，值得记一笔：数值指标（100ms 帧 RMS 的标准差）
      反而说新「轻」档比老的 250ms 版更"抖"（34.2 → 36.9），
      但听感明显更好 —— 因为 release 从 250ms 收到 80ms 之后，
      声音一停那层噪声不再"滞留"。**这一项只能靠耳朵，参数是听出来的、不是算出来的。**
  · **去齿音（de-esser）**：四档（关/轻/标准/强），专治人声发尖、齿音、
    细碎点击声。零依赖 —— 用 ffmpeg 自带的 `sidechaincompress` 搭的：
    主路不动，5~10kHz 单独当侧链，**只有尖刺那一瞬间才压**，
    不像固定 EQ 那样一削就整体发暗。
    实测（同一条素材）：轻/标准/强 把 5~10kHz 尖刺压低 3.0 / 5.7 / 7.3 dB，
    整体响度仍打在 -16 LUFS（偏差 ≤0.23 dB）。
    设计上有两个坑都踩过了，写在这里免得以后重犯：
      ① 阈值不能贴着 RMS。这条素材 5~10kHz 的波峰因数是 25~30 dB
         （峰值 -2、RMS -31 dBFS），阈值设成 -28 dBFS 就几乎一直在压，
         整条被压小 5.4 dB —— 那不是去齿音，是全程压缩。
         正确做法是把阈值卡在 RMS 和峰值之间（-18 ~ -25 dBFS）。
      ② 去齿音压的正好是峰值，所以**必须把它放进测量链**里再算增益，
         否则最终响度会低于目标（实测「轻」低 1.2、「强」低 4.0 dB）。
         现在的做法：先垫一个把素材拉到标称响度的 G1 → 过一遍去齿音
         → 量出真实响度 → 再算补差增益 G2。
  · 响度、峰值一律用 ffmpeg 的 loudnorm/astats **真测**，不靠估算。

【三、怎么证明它真起作用了（不靠"感觉好一点"）】

  这一版最花心思的不是滤镜，是**证据**：

  · 界面上直接显示修完的实测响度 / 真峰值 / 剪掉了多少秒
  · 输出目录留一份《音频修复记录》：每个文件走了哪条链路、
    每个阶段用了什么参数、有没有降级，全部落纸
  · **日志三模式共用**：左下角那块「运行日志」原来建在视频页里，
    一切到「音频」模式整块就被 pack_forget 掉 —— 阶段日志照写、
    用户一个字都看不到（等于白测）。现在它搬到三种模式共用的底栏，
    `audio_fix` 每打一行也抄一份给界面（`run_audio_pipeline(..., 日志=回调)`）。
    实测 9 个阶段小标题（源 / 修复前 / 第一遍 / EQ 后实测 / 增益策略 /
    频段自检 / 修复后 / 剪掉静音 / 记录已写入）一行不落。
  · **频段自检**：把 80~300Hz 和 1.5k~4k 两段实际量一遍再对比。
    发现几乎没变化（比如 EQ 风格选错）就在记录里提示 ——
    这个自检是在本地实测里抓到"整条链路等于没动"之后才加的

【四、AI 模型做成可插拔外挂（默认关）】

  自带 DSP 治不了的（持续底噪、突发杂音），可以挂 AI 模型。
  做法上把「稳」放在第一位：

  · 外挂在 `audio_plugin/` 里，**跑在子进程**里，用一行 JSON 交互，
    不是 import 进来 —— 它崩了、卡了、缺依赖，主程序一点事没有
  · 任何异常（不在 / 缺依赖 / 崩 / 超时）→ **自动降级成 DSP**，
    日志打一行 ⚠️，《音频修复记录》留痕，绝不弹窗打断
  · 模型可以用**另一个 Python 解释器**（很多 AI 库要 3.11+），
    路径填「音频修复_Python路径」；填错了也只是降级
  · 链路是**数组**（如 `["dsp","dpdfnet2"]`）：便宜的先跑、
    把死寂剪掉之后再把剩下的交给贵的模型，省算力

  实测（DPDFNet2，一条 30 秒助眠素材）：80~300Hz 只降 0.1 dB、
  1.5k~4k 降 1.2 dB、>8kHz 降 5.9 dB，响度 -14.6 → -15.0，
  速度约 2.7 倍实时（58 分钟素材约 20 分钟）。
  说人话：**它主要吃高频噪声，不负责去闷** —— 去闷还是靠 EQ 那一段。

  ⚠️ 权重是别人的模型，不在工具包里，要用得自己下。
     另外两个槽位（gtcrn / frcrn）目前是空壳：选了不崩，
     会走降级路线，但不会真跑模型。

【五、这一版没做的事】

  · **音频整套只在 Linux 上实跑过**，Windows / macOS 一次没跑
  · 没做「自动判断该用哪个 EQ 风格」—— 这个得靠听，工具只负责量
  · 没做降噪的 DSP 方案（试过，容易把环境音一起抽走，宁可交给 AI 那档）
  · 没做音频的「批量队列重排」—— 还是按文件顺序一个一个来


════════════════════════════════════════════════════════════
【已修复的坑】（这些都是实际踩出来的）
════════════════════════════════════════════════════════════

1. ffmpeg 会「偷读」输入流
   在循环里调用 ffmpeg 而不关掉它的 stdin，它会把后面的数据当命令吃掉，
   结果循环拿到脏路径、整批卡死在 "Enter command:" 上，看起来像死机。
   → 所有调用都加 -nostdin（其它命令行工具加 </dev/null）

2. CRLF 幽灵字符
   .sh 被 Windows 编辑器一改行尾就变成 CRLF，跑起来一堆
   "$'\r': command not found"。
   一开始想在 bash 脚本里自愈 —— 失败了，因为 bash 读到 CR 就已经崩了，
   它根本没机会自救。→ 改成让 Python 端在启动时自动把行尾修回来。

3. ffprobe 看不见 VP9 的 alpha
   不加参数它会把带透明的素材报成 yuv420p，让你以为透明丢了。
   → 校验时必须加 -c:v libvpx-vp9（README 第八节写了）

4. Windows 子进程中文编码
   上面 v0.3 说过。它用 ANSI 代码页（简体中文机器上是 cp936）往管道
   写中文，而 GUI 按 UTF-8 读 → 满屏乱码。
   这个 bug 在 Linux 上永远复现不出来（Linux 默认就是 UTF-8），
   幸好有台 Win10 才抓到。

5. macOS 的 .app 包结构
   见 v0.3。

6. 压缩包没带 UTF-8 文件名标志位 → 中文名变 #U4e00#U952e 这种乱码
   👀 顺便一个猜测：桌宠发行版里那批 #Uxxxx 素材名，
      很可能就是这个环节产生的，不是谁故意加密。
      用 7-Zip / WinRAR 解压一般就正常。
   本工具包从 v0.1 起就用 Python 的 zipfile 打包，自动带标志位。

7. 空 QRegion 不是"空"，是"清除"
   （这条是桌宠补丁那边的，顺带记一下）
   Qt 会把空的 QRegion / QBitmap 当作 clearMask()，等于恢复整块矩形输入区。
   想要"没有输入区"必须用退化的 1×1 非空区域。

8. ffmpeg 的 alimiter 默认会"偷偷回加音量"
   `alimiter` 的 level 参数默认是 true，它会做自动增益补偿，
   实测凭空多出约 +1 LU。做响度测量的链路里必须写 `level=false`，
   不然你以为打到 -16，实际是 -15。

9. 响度和统计的输出位置跟想的不一样
   · `loudnorm` 的 JSON 是打到 **stderr** 的，只抓 stdout 会一个数字都拿不到
   · `astats` 在一条命令里分多路输出时，**输出顺序和分支顺序对不上**，
     只能按标签 `Parsed_astats_<序号>` 自己排序认领
   → 这两条都是"跑起来没报错、数字却是错的"那种坑，比报错更难查。

10. opus 音轨塞进 mp4 = 哑巴
    封回视频时如果写 mp4/mov，必须把音频转成 AAC。
    webm/mkv 才用 opus。（这条和当初"mp4 装不下 alpha"是同一类问题：
    容器和编码的搭配不能凭感觉。）

11. tkinter：工作线程碰一下 tk 变量就炸
    后台线程里读 `tk.StringVar` 会报 "main thread is not in main loop"，
    报错位置还不在出问题的那一行。
    → 规矩改成：GUI 线程先把设置**快照成普通 dict**交给线程，
      线程要改界面就只往 queue 里丢消息，由 `after()` 轮询取走。

12. 音频「跑完跟没跑一样」也是被实测抓出来的
    最初那版快修跑完，主观上"好像好一点"，一量：
    80~300Hz 只动了 0.1 dB —— 整条链路对那条素材等于没动。
    原因不是 bug，是 EQ 策略没跟素材类型对上。
    → 加「EQ 风格」开关 + 每跑一次都做频段自检并写进记录。
    教训：**主观"听着有变化"不能当验收**。

13. 往 `__init__` 中间插方法，把构造函数的尾巴吃进了新方法体
    给新手卡片加「跟着模式换文案」时，方法定义插在了 `__init__` 中间，
    于是原本属于构造函数的那几行（提示行 + 两个按钮 + 摆位置）
    被吞进了新方法的函数体。后果：**每切一次模式就往卡片上重贴一套按钮**，
    卡片越切越长，用户截图来问"你又复制粘贴了啥"。
    → 教训：加新方法时**先找到前一个方法的结束位置**，
      别用「替换一行」的方式插进去；插完 `sed -n` 看一眼边界。
      这个 bug 靠肉眼看一遍代码就能发现，但只有真去点一遍模式才会暴露，
      所以顺手在冒烟测试里加了两条：卡片按钮必须正好 2 个、提示行正好 1 行。


14. 窗口只给尺寸不给位置，最下面的「运行日志」被屏幕边缘切掉
    原来只写 `geometry("1080x640")`，位置交给窗口管理器决定 ——
    实测有一次被摆到 y=474，640 高的窗子下沿到了 1114，屏幕才 1080，
    底下那块日志正好在屏幕外。用户看到的现象是"日志怎么没了"。
    → 现在 `_摆好窗口()` 自己按屏幕算：宽 min(1080, 屏宽-40)、
      高 min(860, 屏高-80)、居中摆，保证整扇窗都在屏幕里。
      顺带一个实测坑：**`wmctrl -lG` 报的 y 比真实客户区顶部低约 24px**，
      照着它算点击坐标会整体点偏一行（自动化点按钮时踩过）。

15. AI 修复模型会**自带一层本底噪声**
    把一条「尾部是真·数字静音（-240 dB）」的素材过一遍 VoiceFixer，
    尾巴就变成 -64 dB 的嘶声 —— 神经声码器重新合成时把本底带进来了。
    常规打法都救不了：DPDFNet2（-74.6）、afftdn 频谱降噪（-64.5）基本无效；
    最后靠**噪声门**（agate）压到 -98.7 dB，且内容完全不受影响。
    教训：用任何生成式/重合成模型，**都要检查安静段落**，
    别只听响的部分 —— 底噪专门在"没声音"的地方露头。
