DSH Pet 插帧工具 · 一键自检
=====================================================

一句话：**双击「一键自检」，等它跑完，把生成的「自检报告.txt」反馈给作者。**
不用配置任何东西。


一、怎么用
-----------------------------------------------------
1. 双击对应你系统的文件：

     Windows  →  一键自检.bat
     Linux    →  一键自检.sh
     macOS    →  一键自检.command

2. 等它自己跑完（快的话十几秒，慢的话一两分钟）

3. 文件夹里会多出一个 **自检报告.txt**
   —— 把它提交反馈即可，别的都不用管。

   同时还会多一个「自检输出/」文件夹，那是测试产物，
   留着没用，随手删掉不影响任何东西。


二、它会做什么
-----------------------------------------------------
* 记录系统和 Python 的信息（操作系统、版本、**各种编码** —— 查中文乱码全靠这个）
* 找 ffmpeg / ffprobe / rife-ncnn-vulkan，报告找没找到、在哪
* 找不齐就告诉你缺哪个、去哪下（**不会报错崩掉**）
* **找齐了就真跑一次转换**（拿自带的测试素材，插到 48fps），
  再校验输出规格对不对 —— 不是只看看、是真跑
* 所有东西都会写进「自检报告.txt」


三、需要准备什么
-----------------------------------------------------
**必须**：Python 3.8 以上（Windows 上装的时候记得勾 "Add Python to PATH"）
         没有 Python 也没关系 —— 双击后会直接告诉你，把这句话反馈给作者即可。

**可选**：ffmpeg / ffprobe / rife-ncnn-vulkan
         有的话它会接着做真转换测试；没有的话它只报告"缺什么"。
         想补的话，把它们放进**工具包根目录**（也就是本文件夹的上一级，
         和 插帧.py 放在一起）就行 —— 跟正式工具找的是同一个地方。


四、关于自带的测试素材
-----------------------------------------------------
`测试素材/` 里有两个小片段（共约 800 KB），一个体积最小、
一个动作幅度大，用来验证"能不能跑通"最合适。

**它们只用于测试，跑完可以随手删掉**，不影响任何东西。


五、这份自检和工具包的关系
-----------------------------------------------------
从 v0.8 起，自检就**直接装在工具包里面**了（就是你看到的这一层），
不再单独发一个包。所以你要做的就一件事：

    解压工具包 → 先进「自检」双击跑一遍 → 报告没问题了再干活

好处是：正式开跑之前先体检一遍，缺什么、错在哪，一眼就看得出来 ——
而不是等插帧跑到一半才发现 rife 没配好。

另外，它跟正式工具**共用同一套查找规则**：工具包 config.json 里
填过路径就优先用你填的，没填就跟正式工具一样去 PATH 和目录里找。
所以哪怕你什么都没配，它照样能给你一份说得清楚的报告。

要是它和正式工具**结论不一致**（比如自检说找得到、正式工具说找不到），
那就是个 bug，请把两份输出一起反馈。


六、如果连双击都没反应
-----------------------------------------------------
先看同目录（上一级）的「打不开看这里.txt」——
窗口不出来 / 权限不够 / 行尾是 CRLF / 缺 tkinter，都在上面。

还是不行就在终端 / 命令行里手动跑一次，把报错贴出来：

    cd <这个目录>
    python 自检.py        （Windows）
    python3 自检.py       （Linux / macOS）

（Windows 上也可以按 Win+R，输入 cmd，然后一路 cd 过去。）
